# PosBotTlg — Telegram-касса для ювелирного магазина

Telegram-бот для учёта продаж, возвратов, скупки, trade-in, инкассации и склада в магазинах
**ЦУМ** и **Отау Сауда**. Сотрудники работают с кассой прямо в Telegram, администратор получает
отчёты в Excel и управляет персоналом.

Стек: Python 3.12 · [pyTelegramBotAPI](https://github.com/eternnoir/pyTelegramBotAPI) · FastAPI · MySQL · Docker Compose · Caddy · GitHub Actions

---

## Возможности

### Касса — все роли
| Операция | Как работает |
|---|---|
| **Продажа** | Чек из одной или нескольких позиций: артикул → сумма (не ниже минимальной цены, цена по прайсу — одной кнопкой) → «Ещё товар» или способ оплаты → подтверждение. Остатки уменьшаются; в чеке сохраняется цена по ценнику на момент продажи — для анализа скидок. |
| **Возврат** | Артикул → выбор продажи из списка за 60 дней → сумма (по умолчанию полная) → способ выплаты. Товар возвращается на склад, повторный возврат той же продажи невозможен. |
| **Скупка** | Изделие нашего магазина по артикулу (вернётся на склад) или любое изделие без артикула: металл, вес, описание → цена → способ выплаты. |
| **Trade-In** | Сдаваемое изделие и его оценка → новый товар и его цена → бот сам считает доплату: платит клиент или выплачиваем мы. |
| **Инкассация** | Изъятие наличных из кассы с комментарием. |
| **Отчеты** | Сводка в чат + Excel по всем операциям: сегодня, вчера, неделя, месяц, прошлый месяц или любой период. |

Способы оплаты: **Наличные**, **Безналичные**, **Kaspi**.

### Склад — менеджер и администратор
- Добавление товара (пошагово, с проверкой цен), пополнение остатков, Excel-отчёт об остатках с итогами по магазинам.
- **Ценники** — PDF ровно под размер этикетки термопринтера (по умолчанию 30×20 мм — рулон «2×3» для Xprinter XP-365B): название, металл и проба,
  вес, размер, вставки, крупная цена, **QR-код с артикулом** и **штрихкод Code128** для обычных сканеров
  (длинный артикул в штрихкод не помещается — тогда в нём короткий код товара `#<id>`, касса его понимает). Для выбранных артикулов, новых поступлений или
  всего магазина; по одной на артикул или по количеству на складе.
- **Импорт каталога** из Excel/CSV (например, выгрузки Paloma365): колонки распознаются по заголовкам,
  тип и металл — по названию и пробе. Сначала предпросмотр с ошибками по строкам, потом загрузка одной транзакцией.

### Инструкции для сотрудников
`https://<домен>/help` — инструкции [кассира](web/manual/kassir.md), [менеджера](web/manual/manager.md) и
[администратора](web/manual/admin.md) в браузере (открываются без входа, их можно отправить новому сотруднику).
Ссылка на инструкцию своей роли — в `/help` бота, в меню админки («Справка») и на кассе для ПК.

### Касса-приложение (Telegram Mini App) — все роли
Кнопка «📷 Касса» рядом с полем ввода в боте. Продавец сканирует QR на ценнике камерой телефона,
видит товар с ценой и минимальной ценой, выбирает способ оплаты и подтверждает продажу. Внизу — свои продажи за день.

### Касса на компьютере — все роли
`https://<домен>/kassa` в любом браузере на ПК в магазине. Вход без паролей: на экране QR-код, продавец
сканирует его камерой телефона, бот спрашивает «Войти?» — касса открывается под его именем на 14 часов
или до кнопки «Выйти». Все операции бота: продажа, возврат, скупка, Trade-In, инкассация и итоги смены
с журналом операций и печатью. Артикул вводится с клавиатуры или USB-сканером: обычный (1D) читает штрихкод ценника, 2D — и QR. Работа с клавиатуры:
`Enter` — дальше, `Esc` — отмена, `1–3` — способ оплаты, `Alt+1…6` — разделы. Для сенсорных моноблоков —
экранная клавиатура (цифры, русская, казахская, латиница; на сенсорных экранах включается сама, системная
клавиатура при этом не всплывает). Операции те же, что в боте, поэтому отчёты и остатки общие.

### Веб-админка — менеджер и администратор
Вход по одноразовой ссылке из бота (кнопка «Веб-админка»). Сводка дня и месяца, товары с поиском и
редактированием, импорт каталога, ценники, отчёты по кассе с выгрузкой в Excel, персонал (администратор).

### Персонал — администратор
Добавление сотрудника, смена роли и телефона, деактивация. Изменения действуют сразу, даже если сотрудник уже в боте.

### Автоматически
- **Ежедневный отчёт** (по умолчанию в 23:00) — администраторам или в заданный чат.
- **Уведомление о низком остатке** (по умолчанию в 09:00) — администраторам и менеджерам, только по товарам с включённым отслеживанием.

### Удобства
- Вход по кнопке «Поделиться номером», номер в любом формате (`+7…`, `7…`, `8…`). После перезапуска бота входить заново не нужно.
- «Отмена», `/cancel`, «Назад» и кнопки меню прерывают любую операцию.
- Суммы — `15000`, `15 000`, `15000,50`; даты — `ДД.ММ.ГГГГ`.
- Все операции пишутся в БД транзакционно: при ошибке бот прямо сообщает, что операция не прошла.

## Отчёт по кассе

В чат приходит сводка, в Excel — листы **Сводка, Продажи, Возвраты, Скупка, Trade-In, Инкассация**.

Движение денег считается по каждому способу оплаты:

```
+ продажи  − возвраты  − скупка  ± доплаты trade-in
```

Остаток наличных за период = движение по «Наличные» − инкассация.

## Быстрый старт (локально)

Нужны Docker и токен бота от [@BotFather](https://t.me/BotFather).

```bash
git clone https://github.com/azazelo4/PosBotTlg.git
cd PosBotTlg
deploy/bootstrap-env.sh .env      # создаст .env: пароли БД и ключ шифрования
docker compose up -d --build
docker compose exec web python -m setup_code   # код для мастера настройки
```

Открыть <http://127.0.0.1:8000/setup>, ввести код, токен бота, магазины и свой номер телефона —
бот запустится сам. Затем в Telegram: `/start` → «Поделиться номером». Таблицы БД создаются автоматически.

> Один токен — один запущенный бот. Если бот уже работает на сервере, для локальной разработки заведите отдельного тестового бота, иначе Telegram вернёт ошибку `409 Conflict`.

## Настройки

**Мастер `/setup`** — один раз после установки: токен бота, ИП и ИИН/БИН, магазины, первый
администратор, адрес веб-админки, часовой пояс, размер ценника, фискализация (необязательно).
Защищён одноразовым кодом: `docker compose exec web python -m setup_code`. После настройки закрывается.
Галочка «Демо-данные» добавляет пример каталога (артикулы `DEMO-…`) и операций за две недели — для показа
и обучения; удаляются одной кнопкой в «Настройках» вместе со всеми операциями с демо-товарами.

**Страница «Настройки»** веб-админки (администратор) — всё то же и остальное: время отчёта и уведомлений,
порог остатка, строка на ценнике, импорт, Webkassa. Секреты (токен, пароль и API-ключ Webkassa) хранятся
в БД зашифрованными и на странице не показываются; в журнале изменений — кто и когда, без значений.
Смена токена, часового пояса или расписания перезапускает бота сама (до минуты), остальное применяется сразу.

**Файл `.env`** создаёт `deploy/bootstrap-env.sh` (при деплое — автоматически). В нём только то, что нужно
до запуска приложения:

| Переменная | По умолчанию | Описание |
|---|---|---|
| `MYSQL_USER` / `MYSQL_PASSWORD` / `MYSQL_DATABASE` / `MYSQL_ROOT_PASSWORD` | генерируются | Контейнер MySQL |
| `DB_HOST` / `DB_USER` / `DB_PASS` / `DB_NAME` | из `MYSQL_*` | Подключение приложения к БД |
| `POSBOT_MASTER_KEY` | генерируется | Ключ шифрования секретов в БД. **Не терять и не менять** |
| `WEB_SECRET` | генерируется | Ключ подписи cookie веб-админки |
| `TZ` | `Asia/Almaty` | Часовой пояс контейнеров (логи) |
| `LOG_LEVEL` | `INFO` | Уровень логов |

Пароли и ключи генерируются **один раз** и больше никогда не меняются скриптом (MySQL принимает пароль
только при создании базы). Любую настройку из веб-админки можно задать и в `.env` под тем же именем
(`TOKEN`, `WEB_URL`, `LABEL_WIDTH_MM`…) — тогда она главнее базы и в админке только для чтения.
Так продолжают работать установки, где токен лежит в секретах GitHub.

## Деплой

Push в ветку `POS-Bot` → GitHub Actions прогоняет проверки и тесты → self-hosted runner на сервере
пересобирает и перезапускает контейнеры.

- [`docs/INSTALL.md`](docs/INSTALL.md) — **установка для нового ИП** одной командой из готового образа, выпуск версий и ключи доступа для клиентов.
- [`DEPLOY.md`](DEPLOY.md) — установка runner, первый деплой, мастер настройки.
- [`docs/DEPLOY_CLOUD.md`](docs/DEPLOY_CLOUD.md) — пошагово для **VPS is\*hosting (Казахстан)**: сервер, runner, бэкапы БД, перенос данных, обслуживание.
- [`deploy/setup-server.sh`](deploy/setup-server.sh) — подготовка чистого Ubuntu-VPS одной командой (Docker, swap, firewall, бэкапы).
- [`deploy/cloud-init.yaml`](deploy/cloud-init.yaml) — то же для провайдеров с cloud-init.
- [`deploy/backup.sh`](deploy/backup.sh) — ежедневный дамп БД с ротацией и копией в Object Storage.

## База данных

Схема описана в [`schema.py`](schema.py) и применяется автоматически при каждом старте бота:
на пустой базе создаются все таблицы, на существующей — добавляются недостающие колонки и индексы.
Данные при этом не трогаются, повторный запуск ничего не меняет.

| Таблица | Что хранит |
|---|---|
| `stores` | Магазины: название, адрес, активен. Меняются в веб-админке («Магазины») |
| `users` | Сотрудники: телефон, роль, магазин, активность, привязанный Telegram-чат |
| `products` | Товары: артикул, магазин, металл, проба, тип, вес, размер, вставки, цены, остаток |
| `sales` | Продажи (с магазином товара на момент продажи) |
| `returns` | Возвраты (по одной на продажу) |
| `buybacks` | Скупка у клиентов |
| `trade_ins` | Обмены с доплатой |
| `cash_withdrawals` | Инкассация |
| `web_login_tokens` | Одноразовые ссылки входа в веб-админку |

**Магазины** добавляются, переименовываются и отключаются в веб-админке (раздел «Магазины», администратор).
Магазин операции: продажа — магазин товара, возврат — магазин продажи, trade-in — магазин нового товара,
скупка и инкассация — магазин сотрудника; если сотрудник работает во всех магазинах, бот спросит.
Отчёты строятся по всем магазинам с разбивкой или по одному.

**Металлы и типы изделий** — списки `METAL_TYPES`, `PRODUCT_TYPES` в `schema.py` (на существующей базе
дополнительно `ALTER TABLE products MODIFY ...`).

## Разработка

### Как устроена операция

Каждая многошаговая операция хранит текущий шаг в `user_state[chat_id]` с префиксом
(`SALES_`, `RETURN_`, `BUYBACK_`, `TRADEIN_`, `WITHDRAWAL_`, `REPORT_`, `STOCK_`, `UM_`),
а введённые данные — в `user_data[chat_id]['op']`. Чтобы добавить новую:

1. Создать `handlers/<что-то>_handler.py` с функциями шагов.
2. Вход по кнопке — `is_button("Текст", *роли)`, шаги — `in_state("ПРЕФИКС_ШАГ")`.
3. Зарегистрировать отмену: `register_simple_cancel("ПРЕФИКС_", "Название")`.
4. Запись в БД — функция с `@with_transaction` в `database.py`, она возвращает `(успех, результат)`.
5. Подключить `register_*` в `main.register_handlers()` и добавить кнопку в `buttons.py`.

### Тесты

Сценарные тесты прогоняют каждый процесс через настоящий диспетчер бота и реальную MySQL,
подменяя только Telegram API. Нужна запущенная MySQL 8+ (или MariaDB 10.11+) и пользователь
с правом создавать базы:

```bash
pip install -r requirements.txt -r requirements-dev.txt
TEST_DB_HOST=127.0.0.1 TEST_DB_USER=root TEST_DB_PASS=root TEST_DB_NAME=bot_test pytest -q tests
```

Быстро поднять MySQL для тестов:

```bash
docker run -d --name mysql-test -e MYSQL_ROOT_PASSWORD=root -e MYSQL_DATABASE=bot_test -p 3306:3306 mysql:8.4
```

В CI тесты идут на MySQL 8.4 и latest при каждом PR и перед каждым деплоем.

### Правила для веток

- Работа — в отдельной ветке, PR в `POS-Bot`. Merge в `POS-Bot` = деплой.
- Для цепочки PR (второй основан на первом) не нажимайте «Update branch» после мержа первого:
  GitHub сам переключит базу, а конфликт лучше разрешить вручную, сверив diff.

## Безопасность

- Секретов нет ни в коде, ни в репозитории, ни в настройках GitHub: пароли БД — в `.env` на сервере (права 600),
  токен и ключи сервисов — в БД, зашифрованы ключом из `.env`.
- Мастер `/setup` открыт только до первой настройки и только с кодом с сервера; 10 неверных кодов — блокировка на 10 минут.
- MySQL наружу не публикуется, Adminer слушает только `127.0.0.1:8080` — доступ через SSH-туннель.
- Вход принимается только по собственному контакту пользователя, пересланный чужой контакт отклоняется.
- Деактивированный сотрудник теряет доступ сразу — и в боте, и в веб-админке.
- Веб-админка: вход только по одноразовой ссылке из бота (10 минут), подписанная cookie, CSRF-токены в формах.
- Mini App: каждый запрос подписан Telegram (`initData`), подпись проверяется токеном бота; кассу открывает
  только тот, кто вошёл в бота по номеру телефона.
- Касса ПК: вход подтверждается в боте тем, кто уже вошёл в него по номеру; одноразовый QR живёт 5 минут и
  действует только в браузере, который его показал. Роль и активность проверяются при каждом запросе.
