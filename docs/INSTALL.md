# Установка для нового ИП

От заказа сервера до первой продажи — около 10 минут. Знать Docker и Linux не нужно.

Нет сервера и белого IP — можно поставить на ПК в магазине: см. [«Маленькая точка»](#маленькая-точка-пк-в-магазине-без-белого-ip).

## Что понадобится

| Что | Где взять |
|---|---|
| VPS с Ubuntu 22.04 или 24.04, от 1 ГБ RAM и 15 ГБ диска | любой хостинг, например is\*hosting (Казахстан), тариф Start |
| Ключ доступа к программе | выдаёт поставщик (см. раздел «Для поставщика» ниже) |
| Бот в Telegram | [@BotFather](https://t.me/BotFather) → `/newbot` → скопировать токен |
| Домен (желательно) | A-запись `pos.ваш-домен.kz` → IP сервера. Нет домена — подойдёт бесплатный `<IP>.sslip.io` |

## 1. Установка

Скопируйте `install.sh` на сервер (его присылает поставщик) и запустите от root:

```bash
scp install.sh root@<IP>:~
ssh root@<IP>
bash install.sh --key <ключ_доступа>
```

Установщик сам поставит Docker, настроит firewall, swap, автообновления и ежедневный бэкап, скачает
программу и спросит домен (Enter — бесплатный `<IP>.sslip.io`). В конце он напечатает:

```
    https://pos.ваш-домен.kz/setup
    Код настройки: ABCD-EFGH-JKLM
```

## 2. Настройка в браузере

Откройте ссылку, введите код и заполните форму:

- **токен бота** из @BotFather;
- название ИП и ИИН/БИН;
- **магазины** — по одному в строке, эти названия печатаются на ценниках;
- **ваше имя и номер телефона** в Telegram — вы станете администратором;
- часовой пояс и размер ценника (по умолчанию 30×20 мм для Xprinter XP-365B);
- фискализацию Webkassa — только если нужна, её можно включить позже.
- **демо-данные** — по желанию: пример каталога и продаж за две недели, чтобы осмотреться и обучить продавцов.
  Перед началом работы удалите их: «Настройки» → «Демо-данные» → «Удалить демо-данные».

Через 10–20 секунд бот запустится.

## 3. Первый вход и первая продажа

1. В Telegram откройте своего бота → `/start` → **«Поделиться номером»**.
2. **Персонал → Добавить пользователя** — продавцы входят так же, по своему номеру.
3. **Веб-админка** (кнопка в боте) → **Импорт** — загрузить каталог из Excel, или **Товары → Добавить**.
4. **Ценники** — напечатать на термопринтере (масштаб 100 %).
5. Продавец: **Касса → Продажа** или кнопка **«📷 Касса»** — сканировать QR с ценника.
6. Касса на компьютере: откройте `https://<домен>/kassa`, продавец сканирует QR на экране телефоном
   и нажимает в боте «✅ Войти». Удобно для ПК у прилавка: всё то же, что в боте, плюс итоги смены с печатью.

Инструкции для сотрудников — `https://<домен>/help`: отправьте кассирам ссылку `/help/kassir`,
менеджерам — `/help/manager`. Ваша — `/help/admin`.

## Обслуживание

| Команда | Что делает |
|---|---|
| `posbot status` | состояние, версия, связь с Telegram, последний бэкап и копия вне сервера |
| `posbot logs` | логи (`posbot logs bot`, `posbot logs web`) |
| `posbot update` | обновить до последней версии (перед этим — бэкап) |
| `posbot update 1.2.0` | перейти на конкретную версию |
| `posbot backup` | бэкап БД сейчас (автоматически — каждую ночь в 03:30, хранятся 14 дней) |
| `posbot restore /opt/pos-bot-backups/<файл>` | восстановить БД из бэкапа |
| `posbot setup-code` | код мастера настройки, если он ещё не пройден |
| `posbot offsite <адрес>` | копия бэкапов вне сервера (`ssh://…`, `rclone:…`, `https://…`); `posbot offsite test` — проверить |
| `posbot web-url <адрес>` | адрес веб-админки (то же, что в «Настройках») |
| `posbot tunnel …` | туннель для ПК без белого IP (см. «Маленькая точка») |

Всё лежит в `/opt/posbot`. **Сохраните копию `/opt/posbot/.env`** (в менеджер паролей): в нём пароли БД
и ключ, которым зашифрованы токен бота и ключи Webkassa. Бэкапы БД — в `/opt/pos-bot-backups`; копию вне
сервера включает `posbot offsite <адрес>`.

Настройки (токен, расписание отчётов, размер ценника, Webkassa) меняются в веб-админке:
раздел **«Настройки»**, только для администратора.

## Маленькая точка: ПК в магазине без белого IP

Если точка одна и небольшая, сервер и домен не нужны. Бот, касса и админка ставятся на компьютер
в магазине, лучше на отдельный мини-ПК (Intel N100, 8 ГБ, SSD от 128 ГБ) с Ubuntu 24.04. Белый IP,
домен и открытые порты не нужны: бот сам обращается к Telegram, хватает обычного интернета,
даже через мобильный модем.

```bash
sudo bash install.sh --key <ключ_доступа> --local --offsite ssh://posbot@backup.example.kz/srv/backups/shop1
```

В конце установщик напечатает адрес мастера настройки в сети магазина, например
`http://192.168.1.20:8000/setup`, и код. Откройте адрес на этом ПК (или `http://localhost:8000/setup`)
либо с ноутбука или телефона в той же сети (Wi-Fi магазина).

Что работает в таком режиме:

| | Без белого IP |
|---|---|
| Бот: продажи, корзина, возвраты, скупка, отчёты, ценники, импорт | ✅ |
| Касса на этом ПК (`http://localhost:8000/kassa`) | ✅ |
| Касса и админка с устройств в сети магазина (`http://192.168.x.x:8000`) | ✅ ссылки входа из бота открываются только в этой сети |
| Касса-приложение «📷 Касса» в Telegram | только с туннелем (ниже) |
| Админка из дома | только с туннелем |

**Ночью ПК может быть выключен.** Этот режим это учитывает:

- ежедневный отчёт по умолчанию приходит в 20:00, уведомление о низком остатке — в 11:00. Если в это время
  ПК был выключен, отчёт за пропущенный день придёт после включения (только за дни с операциями, не больше
  чем за неделю);
- бэкап делается раз в сутки при первой возможности. Каждый час проверяется, не старше ли последний бэкап
  20 часов, а если копия вне ПК не ушла из-за интернета, отправка повторяется;
- ПК не засыпает: установщик выключает спящий режим. Сообщения, отправленные боту, пока ПК выключен,
  не теряются — бот обработает их после включения.

**Копия бэкапа вне ПК обязательна.** От поломки диска, кражи или пожара защищает только она. Без неё
установщик и `posbot status` выводят предупреждение. Куда копировать:

| Адрес | Что это |
|---|---|
| `ssh://user@host/путь` | сервер поставщика или клиента. Установщик создаст ключ и покажет его: добавьте в `~/.ssh/authorized_keys` этого пользователя |
| `rclone:remote:путь` | облачный диск клиента (Google Drive, Яндекс Диск, S3). Нужен [rclone](https://rclone.org): `rclone config` |
| `https://…/` | загрузка PUT (pre-authenticated request в Object Storage): к адресу добавляется имя файла |

Настроить или поменять позже: `posbot offsite <адрес>`, проверить: `posbot offsite test`.
`posbot status` покажет, когда была последняя копия, и предупредит, если ей больше двух дней.

**Касса-приложение и вход снаружи — через туннель** (по желанию):

- `posbot tunnel tailscale` — [Tailscale Funnel](https://tailscale.com/kb/1223/funnel), домен не нужен.
  Поставьте Tailscale (`curl -fsSL https://tailscale.com/install.sh | sh && sudo tailscale up`), включите
  HTTPS и Funnel в консоли Tailscale. Команда сама пропишет адрес вида `https://pos-shop.tailXXXX.ts.net`
  в настройках.
- `posbot tunnel cloudflare <токен>` — [Cloudflare Tunnel](https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/),
  нужен домен в Cloudflare. В Zero Trust → Networks → Tunnels создайте туннель (тип Docker), скопируйте токен,
  в Public Hostname укажите `pos.ваш-домен.kz` → HTTP → `web:8000`. Затем `posbot web-url https://pos.ваш-домен.kz`.
- `posbot tunnel off` — выключить туннель и вернуть адрес в сети магазина.

**Удалённая поддержка без белого IP:** `--tailscale` при установке ставит Tailscale с SSH. Ссылку входа,
которую он напечатает, откройте в своей учётной записи Tailscale (или в учётной записи поставщика по договору
сопровождения).

**Адрес ПК в сети.** Закрепите его в роутере (DHCP reservation), иначе после перезагрузки роутера он может
смениться. Если сменился: `posbot web-url http://<новый-IP>:8000`.

**Windows.** Работает через Docker Desktop с WSL2, но не рекомендуется: Docker Desktop не стартует, пока
не выполнен вход в Windows, обновления Windows перезагружают ПК и ломают Docker, а бэкапы по cron
нужно настраивать отдельно. Надёжнее — отдельный мини-ПК с Ubuntu рядом с кассой: он стоит недорого и
не зависит от рабочего компьютера продавца.

## Если что-то не так

| Симптом | Решение |
|---|---|
| «ключ доступа не подошёл» | Ключ отозван или скопирован не целиком — запросите новый у поставщика. |
| Страница `/setup` не открывается, ошибка сертификата | Домен ещё не указывает на сервер: `getent hosts <домен>` должен вернуть IP сервера. Подождите обновления DNS. |
| Нет домена и ничего не открывается | SSH-туннель: `ssh -L 8000:127.0.0.1:8000 root@<IP>`, затем <http://127.0.0.1:8000/setup>. |
| Бот не отвечает после настройки | `posbot logs bot`. «Unauthorized» — неверный токен: замените в «Настройках». |
| ПК в магазине: в боте не открывается ссылка админки | Ссылка ведёт на адрес в сети магазина — откройте её с устройства, подключённого к Wi-Fi магазина. Сменился IP ПК — `posbot web-url http://<новый-IP>:8000`. |
| ПК в магазине: «Telegram: НЕТ СВЯЗИ» в `posbot status` | Нет интернета или Telegram недоступен. Как только связь вернётся, бот обработает накопившиеся сообщения и дошлёт отчёты. |
| После обновления не работает | `posbot update <прежняя версия>`; при необходимости `posbot restore` с бэкапом, сделанным перед обновлением. |

## Для поставщика

### Выпуск версии

Образ публикует GitHub Actions в приватный GitHub Container Registry `ghcr.io/azazelo4/posbottlg`:

- каждый push в `POS-Bot` → теги `edge` и `sha-<коммит>` (для проверки, клиенты их не получают);
- тег релиза → `1.2.3`, `1.2` и **`latest`**, который ставят клиенты по умолчанию:

```bash
git tag v1.0.0 && git push origin v1.0.0
```

Образ публикуется только после зелёных проверок, тестов и пробной установки на чистую машину.

### Ключ доступа для клиента

Отдельный ключ на каждого клиента, чтобы его можно было отозвать, не трогая остальных:

1. GitHub → **Settings → Developer settings → Personal access tokens → Tokens (classic) → Generate new token**.
2. Note: имя клиента (например, `posbot: ИП Иванов`), Expiration — по договору (или No expiration).
3. Права: **только `read:packages`**. Больше ничего не отмечать.
4. Отправить клиенту токен и файл [`deploy/install.sh`](../deploy/install.sh).

Отозвать доступ: удалить токен клиента там же. Уже установленная версия продолжит работать,
но `posbot update` перестанет скачивать новые.

> С правом `read:packages` токен читает все приватные пакеты владельца, но не код и не репозитории.
> Если в аккаунте появятся другие приватные образы, заведите для раздачи отдельный аккаунт GitHub
> (например, `posbot-dist`), дайте ему в настройках пакета `posbottlg` роль **Read** и выпускайте
> токены от него; установщику тогда нужно `POSBOT_REGISTRY_USER=posbot-dist`.
